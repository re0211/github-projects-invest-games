## 三、本轮自测与落地（「核实后测对自己有没有用」）

### 1. ✅ 给索引站的三套口径做「只改一处」反例测试 —— 抓到一个真缺口

这是本轮**唯一对自己动刀**的实测。做法：`index.html` 复制到隔离目录，**每次只改一处**，跑 `index_metrics.py`：

| 反例 | 只改这里 | 闸门反应 |
|---|---|---|
| A | 页头数 1141 → 1142 | ✅ **E2 正确报红**（退出码 1） |
| C | 只加一条脚注 `r1141`（不动页头） | ✅ **E2 正确报红**（退出码 1） |
| B | **只删一张卡片**（不动页头、不动脚注） | ❌ **E1–E4 全绿、退出码 0** —— 只有 W1 提示「卡片数与脚注数差 11（历史值 10）」 |

**结论**：三套口径里，`页头数 ↔ 脚注数` 有硬恒等式（E2）保护，
但 **`卡片数` 这一维没有任何硬判据 —— 只有一条「看看就行」的警告**。

危险在哪：增补时要同时改三处（卡片 HTML / 脚注 / 页头）。页头与脚注互相咬合，漏改必被抓；
**但卡片没插进去、或插入失败，闸门全绿。**

> 附带教训：第一遍做反例 B 时**我自己的删除脚本写错了**（一次删掉 17,345 字节，卡片数反而从 1130 变成 2259）。
> 是重做一遍干净版本才拿到上表那行。**反例也要能复现 —— 不然你分不清是工具的错还是你的错。**

**→ 列为下一辑第一待办**：给卡片数补硬判据。
修法**不是**硬编码「差 10」（那会在正常改动时假警，M-0009），
而是让增补脚本**显式声明本版预期卡片数**，闸门与声明值对账。

### 2. ✅ 错误记忆「不可变版本」落地（欠两轮）

新建 **`_tools/mistakes_seal.py`**：
- `--seal`：给 23 条 yml 算 `content_sha256` 写回文件，并生成 `MANIFEST.sha256` 基线
- `--check`：重算比对，**内容被悄悄改写就报漂移**
- 反例实测：篡改任意一条 → **精确报出那 1 条**（不多不少）
- `--audit`：列出缺 `why` 字段的条目（现状 **22/23 缺**，仅报告不阻塞 —— 一次性全阻塞会让闸门永久红灯）

### 3. ⚠️ 这个新闸门自己写坏了它要守护的数据 —— 已修，记为 M-0023

首次 `--seal` 跑完立刻 `--check`，**23 条全部报漂移**。用 `cat -A` 才看清：
第 2、3 行被粘成一行 —— `content_sha256: <64位哈希>status: active`。

根因：**同一个正则被同时用于「剥除」和「替换」**。
剥除时需要连行尾换行一起吃掉（否则原地留空行、摘要对不上）；
但拿它去 `sub` 替换时，被吃掉的换行不会补回来，下一行直接接到哈希值后面。

更值得记的是：**自检当时只验了只读路径（`strip_hash`），没走真实写入路径**，
所以自检全绿而线上写坏。已修：读写各用一个正则 + 自检改为**走真实替换路径**并额外断言换行还在。

→ 新错误记忆 **M-0023「会写数据的闸门，必须先证明自己不会写坏它要守护的数据」**。

### 4. ✅ 房规 +2、文档拆分、索引 +12

- **房规 #50**：能机械化的一律机械化，判断力留给人 —— 分界线要写明
  （检测器：**无**，因为分界线本身只能人判 —— 这正是本条主旨，符合 #33 的「写明为什么判定不了」例外）
- **房规 #51**：把「我们哪里不行」做成门禁（检测器：`_tools/known_limits_check.py`）
  → 该闸门首跑就抓到**自己一个假警**（反例句里「没有例外」被当成局限声明，M-0018 复发），
  → 又抓到**一处标记词不一致**（AGENTS.md 用了弱标记「例外」）—— **三个新闸门全部由自检抓出问题**
- **`game-production-pipeline.md` 994 → 223 行**；各辑增补全文**逐字**移入
  `game-production-pipeline-archive.md`（793 行）
- **`index.html` 1141 → 1153**：第二十九版增补 12 张卡 + 脚注 `[1141]-[1152]`，

## 四、说人话：这轮到底发现了什么

1. **别再拿 ★ 数当「有多少人在用」的代理指标了。** 同一个作者的两个仓库，一个 316★ 零人提问，
   一个 6,086★ 有 13 个人交代码。要看 fork、PR、issue 是谁发的 —— 而且**外部 PR 比 issue 数更硬**：
   `zhangxuefeng-skill` 有 70 个外部 issue 作者，却只有 1 个外部 PR，那是围观不是贡献。
2. **「让 AI 干活」之后，以前嫌麻烦没做的事现在都值得重做一遍** —— 因为「工作量太大」这个反对理由失效了。
   但**判断力那条线要写清楚**，不然会得到一堆永远绿、什么也没守住的闸门。
3. **我们自己的索引站有个洞**：卡片数这一维没人管。改页头、改脚注会被抓，**漏插卡片不会**。
   这次是靠「故意只改一处」测出来的，不是读代码看出来的。
4. **中文技术帖里的 GitHub 链接，抽查四个四个打不开。** 以后看到帖子里点名某个仓库还带具体数字，
   先 `gh api` 一下再信。
5. **工具会写坏它要守护的数据。** 我们新写的「保护错误记忆不被篡改」的闸门，第一版就把 23 个文件全写坏了。
   **保护证据的工具，自己得先被证明是安全的。**
