👀 先看结论

这两条线加上 AI 制作游戏专题，看着不搭界，其实有一根共同的线：都是「把别人的系统拆开看懂，再按自己的意图重新组装」。做游戏是把引擎能力组合成体验，做游戏拓展（解包 / MOD）则是把已经封好的成品拆回可编辑状态；AI 制作游戏则是让大模型直接接管其中最难的一环——内容生成。

所以判断标准也一样：看它的「输入」和「输出」是不是开放、可编程的。 一个只能在图形界面里点点的工具，实用性高但可拓展性低；一个只有 API 没有界面的库，反过来。下面每个项目都按这两条打分；AI 专题另加一项——它能否让「不会写代码的人也能做出来」。

本轮发现：2025-2026 是「AI 制作游戏」真正成型的一年——大模型不再只是写代码补全，而是直接接管剧情生成、对话 NPC、资产生成、关卡编排、整段关卡「一句话生成」。本报告新开「AI 制作游戏」专题单独列出 23 个相关项目，是本轮最大增量。

游戏制作

这条线最容易踩的坑是「选引擎纠结三个月，一行代码没写」。我的建议很直接：想做 2D 小品、要快出成果 → Godot / GDevelop；想做视觉小说 → Ren'Py / WebGAL；只是想玩技术 → Bevy / Phaser。 引擎之间 80% 的能力是重叠的，真正决定成败的是你有没有把第一个 demo 做完。

Godot C++ / GDScript 116.6k 综合首选 每日更新

开源游戏引擎里当之无愧的头牌。整个引擎不到 100MB，秒开，2D 能力业界顶尖，3D 在 4.x 版本后也追上主流。最爽的是 MIT 协议 + 无抽成——你赚多少都是你的。

推荐组合与落地路线

看完几十个项目，最后要给的是「我到底该先动哪个」。下面三条路线按你的两条主线分别给了具体接法，每条都标了所需时间和第一步该做什么。

路线 A · 从解包到 MOD：以 UE/Unity/RPG Maker 三类游戏为例

核心原则：先跑通「解包 → 读结构 → 改值 → 重打包 → 验证」最小闭环，再往上叠工具链。三种引擎的入门路径差别很大：

Unity（IL2CPP 主流版本）：Il2CppDumper 出 metadata → Cpp2IL 反推回 IL → frida-il2cpp-bridge 运行时改行为。配合 REFramework + AssetStudio + UABE 改资源。换皮、汉化、金手指三件事都可以做。

UE（4.27 / 5.x）：RE-UE4SS 注入 Lua 脚本是主流路线，再加 UAssetGUI 改 uasset。运行时改属性比静态改包灵活很多；想做 MOD 工作流建议直接从 Lua 入手。

RPG Maker（MZ/MV）：RPGMakerDecrypter + EasyRPG Editor 处理加密资源；RPGMakerUtils 一键拆图组、改脚本、改对话。完全无门槛，适合作为整个 MOD 链路的「第一站」。

每条路线都已在游戏拓展线收录了具体仓库——先按上面顺序跑通最小例子，再回头读卡片里的「可拓展性/实用性」打分选下一步。

路线 B · 游戏制作：从零到第一个可玩 demo

核心原则：第一个项目必须小到荒谬。 一个能走能跳的角色 + 一个目标，就够了。

1
选引擎并锁死（1 小时决策）

做 2D → Godot；做视觉小说 → Ren'Py（桌面）/ WebGAL（网页）；完全不想写代码 → GDevelop。选定之后三个月内不许换。

工具：Godot [[33]] / Ren'Py [[42]] / WebGAL [[43]] / GDevelop [[35]]
2
照抄一个官方 demo（两天）

不要自己设计。把官方教程的示例从头做一遍，做完就有了一个能跑的东西，成就感比什么都重要。

工具：引擎官方文档 + 中文社区教程
3
加一点你自己的东西（一周）

路线 C · 你的主战场：73 款游戏资料库 × 系统化分析

这是我认为对你价值最高的一条线，因为它直接复用你已有的资产。核心不是"解包"，而是把解包结果变成结构化的洞察。

0
遇到读不动的老游戏时，先查有没有人已经逆向过了

本轮新增的「引擎重实现」子类（OpenMW [94] / openage [95] / xoreos [96] / TRX [97] / Metaforce [98]）本质上就是一群人把某个老游戏的文件格式从零测绘了一遍，并把结果开源。你要解的格式若正好在覆盖范围内，等于白捡一份完整规格说明书。

工具：OpenMW [94] / openage [95] / xoreos [96]
1
先识别引擎，别急着解包（一次批量搞定）

扫一遍目录，按引擎分类：有 game.exe + www/ 多是 RPG Maker MV/MZ；有 .rpa/.rpyc 是 Ren'Py；有 data.xp3 是 KiriKiri；有 package.nw 是 NW.js。分类决定了后面该用哪把钥匙。

工具：先靠文件特征识别，不必装任何软件
2
按引擎选工具，逐个打通

Ren'Py → unrpa 解包 + unrpyc 反编译出剧本；Unity → AssetRipper 或 UnityPy；RPG Maker → RPGMakerDecrypter；其他日系 → GARbro 兜底。

工具：unrpa [[58]] + unrpyc [[57]] / UnityPy [[56]] / AssetRipper [[49]] / RPGMakerDecrypter [[59]] / GARbro [[50]]
3
把流程脚本化，批量处理

这一步是分水岭。手动处理 3 款游戏是玩票，用 Python 脚本批量处理 73 款才是产出。UnityPy 和 unrpyc 都是 Python 的，天生适合干这个。

工具：UnityPy [[56]]（Python API）+ 自己写的批处理脚本
4
把结果变成结构化数据

提取出的剧本、变量、分支、素材清单，存成 CSV/JSON。有了结构化数据，你就能回答"这 73 款游戏的分支密度分布是怎样的"这类原本答不上来的问题。

工具：pandas + 任意可视化
5
接上 AI 制作游戏专题（强烈推荐）

游戏类资料库 + 73 款现成游戏 + AI 制作工具，是你这块最硬的资产——把它们接起来的最短路径：

  • 第 1 步：用 RPGMakerUtils / AssetStudio 拆开一款 RPG Maker 或 Unity 游戏，把脚本/对话导出 JSON；
  • 第 2 步：喂给 inkle/ink 或 YarnSpinner，把现有对话转成可二次编辑的叙事脚本；
  • 第 3 步：用 LDtk 关卡编辑器或 godogen 让 AI 接管关卡设计；
  • 第 4 步：在 Ren\'Py 或 WebGAL 上重做出第一个可玩 demo。

做出来后顺手放到 Steam / itch.io 看反馈，是最便宜的可行性验证。

避坑与合规

这部分比前面所有内容都重要。踩中任何一个，前面的功夫都可能白费。

坑一 · 别被 Star 数骗了，先查"最后一次更新"

本报告里 Star 数最高的是 TradingAgents（102k），但 Star 数是历史累计，不是活跃度。真正要盯的是 pushed_at。

本次核查中发现的"高 Star 但已死"典型：AssetStudio（15.6k，已归档）、UABE（4.1k，作者自己指向继任者）、UnityExplorer（3.1k，已归档）、Backtrader（23.1k，停在 2024-08）、Tushare（15.4k，停在 2024-03）。

规则：最后更新超过 18 个月的项目，除非你有特殊理由，否则不要在新项目里用。

坑二 · License 不是小事，AGPL 会"传染"

本次收录项目里，协议差异极大，挑几个要特别注意的：

  • AGPL-3.0（backtesting.py、ValheimPlus 等）：最严格。你若把它部署成对外服务，原则上需要开源你的服务端代码。商用前务必确认。
  • GPL-3.0（AssetRipper、FModel、LunaTranslator、manga-image-translator）：你改了它的源码并分发，就得同样开源。单纯"使用"不受影响。
  • NOASSERTION / 自定义协议（OpenBB、Cocos、Defold、Flax、StockSharp、GDevelop、Ren'Py）：GitHub 识别不出标准协议，必须逐个去读 LICENSE 文件。尤其是 StockSharp、Cocos 这类有商业背景的。
  • MIT / Apache-2.0：最省心，几乎可以随便用，保留版权声明即可。

坑三 · 解包改包的头号杀手是版本错配，不是工具不行

用 vectorbt 扫一万组参数，一定能找出一组回测收益翻十倍的——那只是你在历史数据上挑出的幸运儿，在样本外必然失效。

三条简单的自保规则：① 留一段从没参与调参的时间段做样本外检验；② 参数越少越好，能用两个参数就别用十个；③ 策略逻辑要有可解释的经济理由，"我也不知道为什么但它回测很牛"基本等于运气。

坑四 · 解包的边界在哪里

技术上能做 ≠ 可以做。几个简单的判断标准：

  • 可以做：对你已合法获取的游戏做学习研究、写分析报告、制作自用 MOD、制作自用汉化补丁。
  • 不要做：把解出来的商业美术/音频素材二次分发；绕过正版验证；破解他人加密后公开传播；把解包内容用于商业再销售。
  • 灰色地带：公开发布汉化补丁。各家厂商态度不一，比较稳妥的做法是做成"需要用户自行提供原版游戏"的增量补丁，不打包任何原始素材。

另外提醒：本报告的评分和推荐仅代表技术视角的观察，不构成投资建议，也不构成法律意见。

坑五 · 本轮新增项目的三个额外提醒

  • 引擎重实现 ≠ 模拟器。OpenMW、openage 这一类是"重写程序"，能加原版没有的功能，但完成度参差——openage、xoreos 至今仍标着未完成。想"玩"先确认完成度，想"学"则完全没问题。
  • 「AI 帮你炒股」类项目要打折看。AutoHedge、AlphaGPT、LangAlpha 这类项目的共同问题是：回测展示很漂亮，风控和实盘工程几乎为零。建议当思路参考，不要当收益来源。
  • 服务端/变速类工具的合规红线更靠前。AzerothCore 开私服、OpenSpeedy 在联网游戏里变速，前者有明确侵权风险，后者必然封号。都只建议在本地、单机、学习场景下使用。
