### 1.1 AI 辅助独立游戏地编：能力边界、工具链与踩坑复盘（CSDN）
https://blog.csdn.net/weixin_29628635/article/details/165661266 · 作者 weixin_29628635 · **2026-09-16**（原创）

**一手三个月实测复盘**（本辑游戏侧信息密度最高、最诚实的一篇；作者一个人做小型开放区域探索游戏，逐周记账）。核心结论一句话：**AI 在地编里能吃 20%~30% 的工作量，且集中在"资产生产"；剩下 70%~80% 是决策、校准、拼装、优化**。硬数字全在账上：
- **预算 60 个人天的地编，实际做完第一版可玩灰盒+美术用了约 140 个人天**（一个人硬扛）；
- 三个月时间账：**AI 工具学习调试约 45h、提示词与参数调优约 30h、生成资产筛选清洗约 55h、返工重做约 40h、真正省下的手工时间约 90h**——**净亏约 80 小时**；但第二个月起好转：**第 1 个月净亏 70h、第 3 个月净赚约 25h**；
- 产出折算：**24 张可平铺地表材质 + 40 张氛围参考 + 约 15 个可用中等精度岩石/建筑体块 + 一张 1009×1009 地形高度图 + 一份程序化铺装规则**——按市场价**不到三千元**；
- **能力矩阵（"可用/半可用/别用"）**：氛围参考图=可用（只看色彩）；地形高度场=半可用；地表基础色=可用；**法线/粗糙度/金属度=别用（全自己从灰度图算）**；建筑岩石造型=半可用（只取大形体后重拓扑）；**植被=别用**（AI 出的数百个模型没有一个过 LOD 检查）；**程序化散布脚本=别用**（AI 写的引擎脚本"接口名一半不存在、参数含义是编的"）；
- 12 个真实坑按损失排序，**合计损失超 110 小时**：高度图尺寸不匹配（应 **8×63+1=505×505**，错成 512 导致整张地形返工，损失 12h）/ 法线绿通道方向反（8h）/ 数据贴图按 sRGB 导入（6h）/ 模型缩放离谱（10h）/ 风格漂移（9h）/ 提示词边际收益递减（14h）/ **让 AI 出关卡俯视图做设计图（空间关系全错，15h）**……
- 尺度硬数字：**角色高度按 1.8m；通道宽不低于 2.5m（双人 4m+）；台阶单级高 0.18~0.2m、进深 0.28~0.32m**；
- 显存账：**1024×1024 BC7 贴图约 1MB、带 mipmap 约 1.33MB**；地形 12 张 1024 约 16MB，加到 60 多张突破 80MB 后 8G 显存机开始卡 → **统一压到 512 后显存砍到 1/4**；**视野内三角面超 400 万帧时间明显上升、超 800 万基本没法玩**；软件光追 1080p 吃 **4~6ms**，硬件加速降到 **2ms 以内**。

→ **可复用性：落地。** ① **"哪些环节是概率性产出可接受的（适合 AI）、哪些必须一次做对（不适合）"** 这条分界线可直接写进房规；② **"AI 给形状和颜色，数值通道（法线/粗糙度/金属度/高度/遮罩）一律自己算"** 是最硬的一条技术红线；③ **"AI 生成物是毛坯不是成品"** 与 §2.3 Harness 职责表同向。对"Ren'Py/独立游戏"受众，这篇的地编方法论可平移到视觉小说的背景与场景资产流程。

### 2.1 Codex CLI 使用与斜杠指令实战教程（CSDN · 葡萄城开发者空间）
https://grapecity.csdn.net/6a8fcc9110ee7a33f29f390e.html · 作者 **Java小白笔记** · **2026-08-27**

**一手实测整理**（作者按本机 `codex-cli 0.150.1` + 2026-08-27 核对的 OpenAI 官方 CLI 参考写成，并显式标注"已验证 / 未验证"边界，是本辑 Codex 一条信息密度最高的）。核心判断：**高效用 Codex 不是背命令，而是分清三层控制面**（启动命令定边界 / 会话内 `/` 指令调协作状态 / 自然语言提示定任务）。
- 四种安装入口（macOS-Linux `curl -fsSL https://chatgpt.com/codex/install.sh | sh` / Windows PowerShell `irm .../install.ps1 | iex` / npm `@openai/codex` / Homebrew `--cask codex`）；作者明确警告：**standalone 与 PowerShell 都是"下载即执行远程脚本"，只应从官方域名复制、别用 `sudo` 跑**；
- 权限沙箱是"最重要的安全开关"：`-s read-only` / `-s workspace-write`（默认推荐）/ `-a on-request` / `-a never` / `--add-dir`；危险开关 `--dangerously-bypass-approvals-and-sandbox`，简写 **`--yolo`**——作者强调"它不是提高效果的开关，只是扩大失误与恶意仓库指令的破坏范围"；推荐起点 `codex -s workspace-write -a on-request`；
- `codex exec` 面向 CI：`--json`（JSONL 事件流）+ `-o <文件>`（落最终结论）+ `--ephemeral`（不持久化）+ `--output-schema`（JSON Schema 约束输出）+ `--skip-git-repo-check`；
- 会话内 `/` 指令：`/plan`、`/goal`（持续追踪目标，可 edit/pause/resume/clear）、`/status`（看 token 余量）、**`/side` 或 `/btw`（临时侧边问答，不污染主线）**、`/fork`（分叉对比方案）、`/review`、`/init`（生成 AGENTS.md）、`/stop`、`/ps`；
- 主结论一句："**把权限、上下文和验证要求说清楚，比不断换模型更能稳定得到可用结果**"。

→ **可复用性：落地。** ① **`--yolo` / `--dangerously-bypass-approvals-and-sandbox` 应进我们的"绝不使用清单"**（与 v21 §5.4 TrustFall 同源）；② **`/side|/btw` 不污染主线 + `/goal` 持续追踪** 是"上下文卫生"的可抄操作；③ 作者"已验证/未验证"分栏的写法值得抄进产出规范。

### 2.4 AI Agent 开发技术点有哪些？一张地图讲清（今日头条）
https://m.toutiao.com/article/7674885001247015467/ · 作者 **优质科技领域创作者** · **2026-08-17**

**三层技术地图**（地基层/进阶层/上线层，附难度与优先级）。可抄的数字与判据密：
- **同一流程写成自然语言 Skill，完成率只有 56%；编译成带类型和前置条件的 Harness 后升到 86%**；
- **工具目录别超过 15 个**——"超过这个数，模型开始『选择困难』，准确率断崖式下跌"；
- **工具调用超过 15 次后，原始对话记录就开始污染上下文**；**记忆分层做对了能省下六成 Token**；
- 工具返回**结构化错误**（带 retryable 标记 + hint 字段）——"工具接口层占了 Agent 工程量的七成"；
- **单步可靠性 90%，串 5 步端到端只剩 59%**——"这就是为什么架构比提示词重要"；

- **地基是 Cordis**（Shigma 的开源 "Meta-Framework"）：DSH 把整个框架 **vendor 进自己仓库**、改名 `@deepseek-ai/cordis`，所有自家包都设为对它的 **peer dependency**；Cordis 的成名使用者是**聊天机器人框架 Koishi**（QQ/Discord/Telegram/微信）；
- 核心理论问题："**有没有一种 programming model，能让动态本身具备类似进程那样的生命周期隔离？**"给出**时间可组合性**（卸载时对共享环境的修改必须被完整逆转）与**空间可组合性**（依赖变化时相关组件自动激活/停用）两个定义；
- **Fiber 六状态**：`PENDING/LOADING/ACTIVE/FAILED/DISPOSED/UNLOADING`；声明 `inject:['tools','shell']` 的插件会停在 `PENDING` 直到依赖出现；
- **`ctx.effect()` 是唯一原语**：所有上下文变更（事件注册 / 提供服务 / 挂子组件 / 定时器 / 状态变更）都归约为一次 effect 调用，返回 disposer；在已卸载 fiber 上建 effect 会抛 `CordisError INACTIVE_EFFECT`；

- 诚实边界："**回调提供了逆，但该逆是否真恢复了效应，是组件作者的责任（obligation），而不是运行时验证的性质（property）**"；
- 与 **Codex 的工程决策对比**：核心循环可替换性（DSH 的 `ReactLoopAgent` 注册为工厂，Codex 循环固定在核心）/ 沙箱位置（DSH 做成能力插件，Linux 走独立原生 Node 扩展调 Landlock）/ 拆包粒度（Codex 上百 crate vs DSH 两百多包）/ 代码编排隔离（Codex 用独立 V8 isolate，DSH 用 `worker_threads`）/ 工具暴露方式（Codex 静态标记，DSH 运行时按 scope 链实时计算可见性）；
