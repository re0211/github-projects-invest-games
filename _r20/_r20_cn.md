### 1. 上下文工程与子智 ——「1M 窗口是危险的创可贴」
- **URL**：https://juejin.cn/post/7685963804388458506
- **平台 / 作者 / 日期**：稀土掘金 · AI研究社_ · **2026-09-16**
- **核心内容**：
  - 一组可引用的实测对比：**全上下文方案准确率 72.9% / 延迟 17 秒 / 每会话 26,000 token**；**选择性记忆检索准确率约 66–67% / 延迟降 91% / token 减 90%**。作者判断：拿 6 个百分点的准确率换 91% 延迟下降，生产里划算。
  - 记忆必须分四类：情景 / 语义 / 程序 / 工作记忆。最危险的操作叫**记忆提升（promotion）**，要设闸门：**会话→用户级允许（偏好与草稿）；会话→租户级只允许已验证事实；会话→全局级运行时绝不执行**。不设闸门会遭遇「护栏静默漂移」和「先例投毒」。
  - 子智能体隔离：协调者显式选择传给每个子智能体的信息，**子智能体输出当作「带出处的工具结果」，不是继承父级权威的指令**；作用域必须继承但**父级工作集不继承**。有团队实测子智能体隔离 vs 共享上下文单智能体，**任务成功率 +90.2%**。失败模式叫「确认偏误注入」——子智能体拿太多历史会锚定先前结论。
  - 一条与我们直接相关的收尾：**裁剪后必须重测任务成功率与完工成本**，否则只是把成本转移到更多次探索上。
- **可复用性**：**参考**。数字漂亮但**没有给出数据集、模型和复现方式**（"有团队实测"无出处），不能直接写进房规。可取的是「记忆提升三级闸门」和「子智能体输出＝带出处的工具结果」这两句判据——它们是可操作的，且我们第十九辑的房规 #36/#40 只管文风不管记忆层级，这是补位。

### 3. Token 成本优化实战：caveman 压缩 65% 输出 + 长上下文「虚假」陷阱全揭露
- **URL**：https://blog.csdn.net/2301_81443758/article/details/162551204
- **平台 / 作者 / 日期**：CSDN · 2301_81443758 · **2026-07-03**（⚠️ 较旧，但内容未被前十九辑收过）
- **核心内容**：
  - **caveman**（19 岁开发者 Julius Brussee，2026-04 起）四档模式：Lite / **Full（默认）** / Ultra / **Wenyan（文言文）**。作者跑了 **10 组真实编程场景**基准：平均 **1214 → 294 token，压缩率 65%**；高压缩率集中在结构化技术解释类（解释 React 重渲染 bug **1180→159，87%**；调试 PostgreSQL 竞态条件 **1200→232，81%**；设置 PostgreSQL 连接池 **2347→380，84%**），低压缩率在需要权衡论述的任务（架构：微服务 vs 单体 **446→310，30%**；重构回调为 async/await **387→301，22%**）。
  - 三臂评测（baseline / terse 指令 / caveman skill）确认：**单纯说"请简洁回答"无效**，因为 RLHF 把"详尽礼貌"标为正面特征；**给具体人设（原始人）约束力远超抽象指令**。
  - 输入端：`/caveman-compress` 把 `CLAUDE.md` 等记忆文件压成原始人语言，实测 **CLAUDE.md 偏好设置 706→285（59.6%）、项目笔记 1145→535（53.3%）、平均 898→481（46%）**。
  - 引 Chroma《Context Rot》（18 个前沿模型）与 RULER：**生产有效上下文 ≈ 广告窗口的 25–30%**。1M 窗口模型 **超过 200K 后就不再表现得像 1M 模型**；具体建议上限：Opus 4.8 1M → **280K（28%）**、Gemini 2 Flash 1M → 300K、GPT-5 200K → 50K。
  - 三大病理：Lost-in-the-Middle（**答案在位置 5–15 时准确率下降 30+ 个百分点**）、Length-Only Floor（纯拉长长度准确率平均 **−7.9%**）、**连贯干扰 > 随机干扰**（所以检索块要用 `## Source N` 原始拼接，不要改写成流畅摘要）。
  - 反直觉结论：引 2026-03 论文《Brevity Constraints Reverse Performance Hierarchies》，**限制输出简短在某些基准上反而 +26 个百分点**。
- **可复用性**：**⚠️ 参考，且必须和我们已有房规对冲着看**。这是我们第十九辑**房规 #40 的正面对撞材料**：`context-mode` #482 因为 Moonshot 在 kimi-k2.5 上的报告**删掉了 22 处 "Terse like caveman" 注入**，理由是损害编码/推理基准；而这篇说 caveman 平均省 65% 且可能提准确率。**两边都有数字、结论相反** → 正确处置是**只取不冲突的部分**：25–30% 有效窗口、`## Source N` 原始拼接、Lost-in-the-Middle 位置评测（取 30 个真实问题把答案块放第 1/5/10/15/20 位测准确率，掉 >20pt 就是上下文太长）。**caveman 本身的"压文风"部分我们不采用**（房规 #40 已判）。

### 4. AI Coding 烧钱如流水？一文讲透 Token 经济学：路由、缓存与上下文压缩如何把成本砍半
- **URL**：https://blog.csdn.net/guwentian/article/details/163989831
- **平台 / 作者 / 日期**：CSDN · guwentian（码龄 4 年） · **2026-08-23**
- **核心内容**：
  - 三件套：①**分层模型路由**（`route(task, est_tokens)`，简单任务走 flash、硬任务走 frontier、`est_tokens > 30000` 强制升档，带超时降级）；②**Prompt Caching**（**前缀变更率压到 5% 以下，输入成本通常降 80%+**，命中后输入单价降到 1/10）；③**摘要式压缩**（`compress_turns(turns, keep_recent=4)`，保留最近 4 轮原文，更早折叠成一句摘要）。
  - 成本口径的量级估算：日均 10,000 次调用 / 平均输入 18,000 token / 输出 2,000 / 缓存命中 30% / 重试率 25% → **约 $495/天、月近 $15k**。
  - 三条生产避坑：**只看单价不看成功任务成本**（重试、工具失败、人工复核都要计入）；**缓存全量可观测会扩大数据面**（日志含 system prompt 与工具返回，必须做脱敏、保留期、租户隔离、访问审计）；**降级不是免费午餐**（降级失败重跑更贵，阈值与重试次数要写进成本模型）。
  - 代码全是纯标准库、可直接 `python route.py` 跑通的骨架。
- **可复用性**：**参考**。我们是个人单机（Ollama + 一个索引站），没有日均 10,000 次调用，路由与缓存的直接收益有限。真正能抄的是**"每任务成本埋点"这一条**——把"模型 / in-out token / 耗时 / 是否重试"记成事件，这是"成功任务单位成本"看板的底座；我们目前只记结果不记成本。另外"头部不变尾部可变"这条**和第十九辑 harness tax 实测（MCP 工具定义占 50%）直接咬合**。

### 5. 几轮对话后 Claude 变笨了
- **URL**：https://juejin.cn/post/7668906037449965574
- **平台 / 作者 / 日期**：稀土掘金 ·（原文首发于作者博客 time-friend.com） · **2026-08-01**
- **核心内容**：
  - **每发出一条 prompt 就自动创建一个快照**，不只记对话，还**快照被修改的文件状态**；按两次 `Escape` 或 `/rewind` 打开回退菜单，可选「只回退对话 / 只恢复代码 / 两者都回退 / 从某节点开始压缩」。检查点随会话保存，**关掉终端回来还能继续回退**。
  - ⚠️ 一条明确的边界：**检查点只追踪 Claude 通过编辑工具做的修改，通过 Bash 命令或外部进程改的东西不在此列**——它不是 git 的替代品。
  - 一个反例（很有价值）：Claude 反复回到一个错误假设时，**用 `/compact` 会把那个错误假设也保留下来**，问题不解决。正确做法：`/clear` 清空 + 更精确的 prompt 重来；要保留上下文就用 `/compact 只保留 API 变更相关的部分，丢掉调试过程`（加 focus 指令）。
  - 土办法：**每完成一个逻辑单元（一个函数、一个组件）就 `git commit` → `/clear` → 再开下一个**。
  - Skill 打包：`.claude/skills/code-review.md → /review`，一个 skill 文件写清"目标 / 读哪些文件 / 输出什么格式 / 怎么验证结果"。
- **可复用性**：**落地**。`/rewind` 快照 + "完成一个逻辑单元就 commit + clear" 是我们已经在做的变体，但**"检查点不覆盖 Bash 改动"这条边界我们没记过**，值得写进房规（我们大量用 Bash 跑 `insert_v*_cards.py` 这类脚本，误以为有快照兜底是有风险的）。`/compact` 会保留错误假设这条也与 #2 呼应。

### 7. AI Agent 记忆系统设计：从短期记忆到长期记忆的工程实践
- **URL**：https://blog.csdn.net/weixin_29051811/article/details/164900274
- **平台 / 作者 / 日期**：CSDN · weixin_29051811（码龄 10 年） · **2026-09-10**
- **核心内容**（**本路最具体的一篇，参数全部给了数字**）：
  - 三条路线对比：A 上下文硬扛（必翻车，引 Lost in the Middle）→ B **Embedding + 向量库** → C 记忆框架自动管理（"hindsight 记忆库"：像人睡前回忆，定期把对话提炼成高浓度长期记忆；双网络＝写入网络判"值不值得记/是否冲突"，读取网络做检索与重排）。
  - **B 路线的具体参数**：中文场景 `bge-m3` 比 `text2vec` / `text-embedding-3-small` 在长文本上更稳；**Chunk Size 200–500 字符**；**Top-K 先取 5–8 条 + 相似度阈值过滤掉低于 0.6 的**；混合检索 **BM25 + 向量加权融合（0.6/0.4）**。
  - **编程 Agent 的三层标配**：项目级长期记忆（仓库结构与规范 → 向量库）／任务级工作记忆（当前分支状态 → **JSON 文件**）／会话级（diff 上下文 → Framework State）。第一层向量化的对象是：文件路径、函数名、类名、commit message、diff 摘要。
  - 两个排查实录：①**记忆污染**（库里同时有"预算十万"和"预算二十万"，召回到旧的）→ 双保险＝写入时冲突检测 + 召回时把 `created_at` 一起给模型 + System Prompt 明写"记忆可能过时，以用户当前表述为准"，作者称**能减少一半以上**；②**召回不准** → 按性价比排序：Top-K 5→10 配阈值 → 混合检索 → 最后才换更强的 Embedding；**写入时打 metadata 标签（偏好/项目约束/决策），召回先按类型过滤再算相似度，效果提升非常明显**。
  - 性能三层优化（召回缓存 / 写入异步 / 摘要攒批），实测**把记忆系统额外开销压到 100ms 以内**。
  - 迁移格式建议：**JSONL，每条一行，字段固定 `id`/`user_id`/`content`/`metadata`/`created_at`/`updated_at`，版本号放文件名或第一行**。
- **可复用性**：**落地**。这篇几乎是为我们的场景写的：我们的 `mistakes/` + `.workbuddy/memory/` 正是"文件型持久记忆"，但**缺 metadata 标签、缺 created_at、缺冲突检测**——这三条可以直接补。**JSONL 固定字段**这条对换机迁移有直接价值（我们第十九辑待办 #7 是 MEMORY.md 瘦身，可顺带做结构化）。

### 8. Agent 都说自己有长期记忆？四层记忆管道的设计真相与五个验证测试
- **URL**：https://blog.csdn.net/qq_40140450/article/details/164714386
- **平台 / 作者 / 日期**：CSDN · 白日放歌须纵久（qq_40140450，码龄 9 年） · **2026-09-09**
- **核心内容**：
  - **四层管道（成本递增、价值递增的阶梯）**：①工作记忆（上下文窗口）②对话历史（会话日志/摘要）③**持久记忆（文件：CLAUDE.md / AGENTS.md，显式写入、人可读、可 git 追踪、可 code review）**④长程记忆（向量库/知识图谱，写入读取都在黑盒，可审计性弱）。作者的核心指责：**把第 1/2 层包装成第 3/4 层卖给用户，是市场乱象的来源**。
  - **五个外部验证测试**（**本条最值钱的部分**）：
    1. **延迟召回**：会话 A 教一条偏好 → **24 小时后**开会话 B 不重提，看行为是否正确。三档判定：直接复述（可能是检索恰好命中）／**行为正确且能溯源到记忆条目（最理想）**／行为错误。
    2. **写入路径审计**：任务结束后立刻 `git diff` / 目录比对 / 查记忆库 API——**宣称记住必须有物理落盘，一条都没落盘直接判负**。给了 SHA-256 快照脚本思路（`snap` → `verify`）。

### 10. Vibe Coding 上线之后：一次 150+ commit 的复盘
- **URL**：https://hanyouqing.com/blog/2026/09/when-vibe-coding-hits-production
