### 6. 《喵僕 | Live2D 拆分準備與 PSD 圖層整理》

- URL：https://www.nekomaido.com/blog/live2d-psd-preparation
- 作者：喵僕（台湾 Live2D 建模站）· 无显式日期
- **本节最"可操作"的一条**，给了两条别处少见的硬结论：
  - **图层效果支持边界（Live2D Cubism 5.3+）**：**支持**一般圖層、圖層混合模式、剪貼蒙版（**需在 Live2D 内重新剪貼 ID**）；**不支持** 蒙版(Layer Mask)、圖層樣式、調整圖層、智慧型物件、文字圖層、向量圖層——**这些必须在 PS 里先转成一般图层再导入**（与官方 `precautions-for-psd-data` 一致）；
  - **命名硬规则**：**避免重名**——"導入時 Live2D 並不會報錯，但後續替換圖層時會出現同名替換錯誤"；建议格式 `[左/右_部位_物體1/2/3]`。
  - 还指出"**拆了合并简单，合并要拆很难**""半透明/有纹理/滤镜特效的图层**完结后再补拆非常困难**，建议画时就分好"。
- 可复用性：**✅ 落地**。理由：这是**做模型前必须先定的图层规范**，两条（不支持的效果先转平、图层别重名）一旦做错就得推倒重来，直接抄进自己的 PSD 交付清单即可。

### 4. 《本地跑大模型 Ollama 爆显存/中文乱码？三步调参顺畅跑起来》

- URL：https://www.renrendaima.com/article/13696.html
- 作者：admin（人人代码）· 发布 **2026-09-01 10:53:25** · 浏览量 **380**
- **本节对"16GB 机器"最直接有用的一条**，给出可照抄的三件套：
  1. **换量化**：`ollama pull llama3.1:8b-instruct-q4_K_M` —— **Q4_K_M 比 FP16 省约 65% 显存**，质量几乎无感；**6G 以下显存用 3B 的 q4 更稳**；
  2. **降上下文与并发**：`OLLAMA_NUM_PARALLEL=1`（每个并发槽都乘上下文占用显存）、`OLLAMA_CONTEXT_LENGTH=2048`（默认 4096，**减半省 1~2G KV 缓存**），或用 Modelfile 的 `PARAMETER num_ctx` 锁死；
  3. **编码与释放**：中文乱码多因终端/调用方非 UTF-8；`OLLAMA_KEEP_ALIVE=0` 用完即释。
  额外：`OLLAMA_FLASH_ATTENTION=1` 支持的架构**提速 20~40%**；**没有全局"显存上限"变量**，靠量化+上下文+并发控。
- 可复用性：**✅ 落地**。理由：**这就是"本地 Ollama 桌宠总爆显存/输出乱码"的标准解**，三条环境变量可直接写进启动脚本；⚠️ 站点是内容站（作者 admin、来源"原创"口径模糊），**数字是通用经验值而非本机实测**，按需自测。

### 1. 《我是如何从零构建一个生产级 AI Agent 框架的》（掘金）

- URL：https://juejin.cn/post/7648193052292939822
- 作者：**争筝**（实习生，项目代号 Haven「健健」）· 发布 **2026-06-07** · 阅读 **86** · 7 分钟
- **架构硬货**：**Coordinator → Dispatcher → Agent 三层调度**；
  - **Coordinator 不用关键词匹配**，直接用 LLM Structured Output 把意图分类为 `coder / researcher / diagnosis / general` 四类并生成 **DAG 执行计划**；
  - **Dispatcher 负责容错**——节点失败触发重试而非整链崩溃（"最初版本一遇到工具报错就挂"）；
  - 调度用 **LangGraph**（要的是"天然支持状态图和 checkpoint"）；
  - **工具全面接 MCP**：覆盖 stdio / HTTP SSE / WebSocket 三种传输；命名空间隔离 `{server}__{tool}`；**工具选择完全交给 LLM，框架层"零意见"只透传**。
- **记忆系统（最值得抄的机制）**：**双轨**——短期=LangGraph 内置 `SqliteSaver` 自动 checkpoint；长期=**对话完成后由辅助模型 `deepseek-v4-flash` 异步提取结构化事实**（"我养了一只猫叫花花" → `{宠物:猫, 宠物名:花花}`）→ 去重 → 存 **SQLite** → 下次会话注入 System Prompt。**理由写得很清楚**：放后台异步=不阻塞响应；用轻量模型=信息提取这类简单任务够了，没必要上大模型；**去重是必须的，否则 memory 膨胀影响注入效率**。
- 人格系统=**配置驱动**（`haven.md` YAML frontmatter + `skills/*.md` 按场景激活），原则："人格是数据，不是代码"。
- **重构复盘**：`Config → Core → Tools → Runtime` **单向依赖链**；删掉自研 `ToolResolver`/`VectorMemory` 改用社区组件；**重构后代码量减少约 30%，功能反而增强**。
- 可复用性：**✅ 落地（当架构蓝本）**。理由：**"deepseek-v4-flash 异步提取 + SQLite 去重 + System Prompt 注入"这套长期记忆，正好是本机本地 Ollama 桌宠缺的那一块，且不依赖任何云服务**。
